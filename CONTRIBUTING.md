# Contributing Guide

Thanks for your interest in contributing! This short guide walks you through the basics of how changes are proposed and reviewed on this repository.

## Proposing changes (pull requests)

1. Fork the repository and create a new branch for your work (`git checkout -b <short-description>`).
2. Make your changes on that branch and commit them with clear, focused messages.
3. Open a pull request against the `main` branch and describe what changed and why.

## Reporting bugs

- Search existing issues first so we don't duplicate effort.
- Include steps to reproduce, expected vs. actual behavior, and your environment.
- Mark the bug as **bug** so it can be picked up quickly.

## Labeling work

- Use `area` labels to describe which part of the code a change touches.
- Use `kind` to flag whether a task is a `bug`, `documentation`, or `enhancement`.
- Keep the three-sentence rule: title it precisely, body it in one or two sentences, and link the related issue.

## Code review

- Reviewers leave comments (not approvals) until the change is stable.
- Authors push follow-up commits to the same branch; the PR updates automatically.
